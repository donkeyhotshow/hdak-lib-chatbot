## Параллельное выполнение (Concurrent Execution)

```
TIMELINE:
    0ms ├─ Пользователь отправляет сообщение
        │
        ├─ detectSearchIntent() выполняется мгновенно
        │
    5ms ├─ checkCatalogAvailability() ЗАПУЩЕН ──┐
        │                                        │
        ├─ searchCatalog() ЗАПУЩЕН ──────┐      │
        │                                │      │
    10ms│                                │      │
        │                                │      │
   200ms│                                │      │
        │ Recommendation search ЗАПУЩЕН ─┼─┐   │
        │                                │ │   │
   500ms├─────────────────────────────────┤ │   │
        │ searchCatalog() вернул результ. │ │   │
        │                                │ │   │
  1000ms├───────────────────────────────┼─┘   │
        │ Recommendations готовы        │ │    │
        │                                │ │    │
  1100ms├────────────────────────────────┼─┤   │
        │                            │ │ │    │
        │ ГОТОВЫ все результаты ────┴─┘ │    │
        │                                │    │
        ├─ buildCatalogContext()        │    │
        │ добавляет результаты          │    │
        │                                │    │
        ├─ LLM получает полный контекст │    │
        │                                │    │
  2000ms├─ LLM начинает отвечать       │    │
        │                                │    │
  3000ms├─────────────────────────────────┤   │
        │ ДОСТУПНОСТЬ КАТАЛОГА готова    │    │
        │ (но это уже не нужно - LLM     │    │
        │  уже начал отвечать)           │    │
        │                                │    │
  4000ms└─ Ответ полностью стримирован
```

**Ключевое преимущество:** Все поиски выполняются параллельно, поэтому ответ не ждет самый медленный поиск.

## Примеры SearchIntent распознавания

### 1. Поиск по названию (TITLE)
```
Input:  "Знайди книгу Война и мир"
Intent: { searchTerm: "Война и мир", searchType: "title" }
Pattern: /(?:знайди|знайти|пошук|шукаю|шукати).*книг[уиі]?\s+[«"']?(.+?)[»"']?$/i
```

### 2. Поиск по автору (AUTHOR)
```
Input:  "Книги Толстого"
Intent: { searchTerm: "Толстой", searchType: "author" }
Pattern: /(?:книги|твори)\s+(?!про\s|з\s|по\s)([А-ЯҐЄІЇа-яґєії\w\s\-]+)(?:\?|$)/i
```

### 3. УДК классификация (UDC)
```
Input:  "УДК 821.161.1"
Intent: { searchTerm: "821.161.1", searchType: "udc" }
Pattern: /УДК\s*([\d.]+(?:\.\d+)*)/i
```

### 4. Поиск по теме (SUBJECT)
```
Input:  "Материалы на тему украинской истории"
Intent: { searchTerm: "украинской истории", searchType: "subject" }
Pattern: /(?:книги|матеріали)\s+на\s+тему[:\s]+(.{3,60}?)(?:\?|$)/i
```

### 5. Ключевые слова (KEYWORD)
```
Input:  "Ключевые слова: искусство, живопись"
Intent: { searchTerm: "искусство, живопись", searchType: "keyword" }
Pattern: /ключов[іе]\s+слов[аи][:\s]+(.{3,120}?)(?:\?|$)/i
```

## HTML Parsing процесс

```
RAW HTML от каталога
    ↓
stripHtml() - удаляет теги, скрипты, стили
    ↓
Текст разбивается на строки
    ↓
Каждая строка проверяется isBookEntry():
  - Содержит "/" (библиографический разделитель)?
  - Содержит год YYYY?
  - Длина > 30 символов?
  - Содержит запятую?
  - Не выглядит как URL?
    ↓ (если все да)
buildBook() парсит поля:
  - Title: До первой запятой
  - Author: От 1й запятой до года
  - Year: Год в скобках {YYYY}
  - Description: Полный текст
  - hasFile: true если [есть файл]
    ↓
BookResult
    ↓
SearchResult {books: [...], total: N}
```

## Обработка ошибок

```
┌─────────────────────────────────┐
│ searchCatalog() / recommedations│
├─────────────────────────────────┤
│                                 │
│ try {                            │
│   fetch(CATALOG_URL)             │
│ } catch {                        │
│   return {                       │
│     books: [],                   │
│     total: 0,                    │
│     unavailable: true  ← ОШИБКА │
│   }                              │
│ }                               │
│                                 │
└─────────────────────────────────┘

checkCatalogAvailability()
    ↓
isCatalogAvailable = false
    ↓
Если searchResult.books.length === 0
    → Отметить как unavailable
    ↓
LLM ЗНАЕТ что каталог недоступен
и может объяснить пользователю:
"К сожалению, каталог сейчас не доступен,
но я могу помочь информацией..."
```

## Производительность

### Типичные времена ответа:

| Операция | Время |
|----------|-------|
| detectSearchIntent() | 1-2 ms |
| checkCatalogAvailability() | 100-500 ms |
| searchCatalog() (local) | 500-1500 ms |
| searchCatalog() (slow) | 2000-3000 ms |
| buildCatalogContext() | 5-10 ms |
| LLM response (first token) | 1000-2000 ms |
| **TOTAL (user sees)** | **~2 сек** |

Благодаря параллелизму, пользователь видит ответ примерно за 2 секунды, даже если каталог медленный.

## Заключение

Система работает как **умный посредник** между пользователем и каталогом ХДАК:

1. Понимает намерение пользователя (поиск, рекомендации)
2. Автоматически ищет релевантные материалы
3. Объединяет результаты с ответом LLM
4. Работает параллельно для высокой производительности
5. Обрабатывает ошибки грациозно
6. Дает пользователю лучший опыт

Это не просто чат - это **интеллектуальный помощник библиотеки**.
